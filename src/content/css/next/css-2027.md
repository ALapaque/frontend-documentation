Il y a six mois, la « logique » de CSS — conditions, fonctions, comptage de fratrie —
vivait presque entièrement dans Chromium, et la maçonnerie native s'écrivait
`grid-template-rows: masonry`. Fin novembre 2026, trois choses ont changé : une série
de fonctions est devenue **Baseline**, Safari teste `if()` et `@function` en bêta, et
la maçonnerie a changé de nom. Reste la question qui décide de ton code : **que
peux-tu écrire sans repli, que dois-tu encore protéger, et sur quoi ne faut-il rien
construire ?**

:::callout{type="info"}
Statuts arrêtés au **27 novembre 2026**. « Baseline » est pris au sens strict : la
fonctionnalité est classée ainsi par le paquet npm `web-features` (3.48.0), la donnée
de référence. Si les trois moteurs la livrent sans ce classement, c'est précisé.
:::

## Bilan 2026 : ce qui est devenu Baseline

Baseline « Newly available » veut dire : livré dans la version stable de Chrome,
Edge, Firefox et Safari, sur ordinateur comme sur mobile. En 2026, c'est presque
toujours Firefox qui a fermé la marche.

| Fonctionnalité | Baseline depuis | Dernier arrivé |
| --- | --- | --- |
| `field-sizing` | 16 juin 2026 | Firefox 152 |
| `sibling-index()` / `sibling-count()` | 18 août 2026 | Firefox 154 |
| `progress()` | 1er septembre 2026 | Firefox 155 |
| `alpha()` | 14 septembre 2026 | Safari 27 |
| `light-dark()` avec des images | 14 septembre 2026 | Safari 27 |
| Scroll-driven animations | 27 octobre 2026 | Firefox 159 |

Concrètement, ce bloc ne demande plus ni JavaScript ni variable posée à la main :

```css
.carte {
  /* stagger : la position dans la fratrie remplace le --i écrit à la main */
  transition-delay: calc((sibling-index() - 1) * 60ms);
  /* progress() : où en est 100vw entre 320px et 1200px ? Un nombre de 0 à 1. */
  --t: progress(100vw, 320px, 1200px);
  padding: calc(1rem + var(--t) * 1rem);
  /* alpha() : la même couleur, avec une autre opacité */
  border: 1px solid alpha(from var(--accent) / 0.3);
}
textarea { field-sizing: content; }   /* le champ grandit avec son contenu */
```

**Pourquoi c'est un cap.** Chaque fonction supprime un contournement :
`sibling-index()` remplace l'index généré par le template, `progress()` la règle de
trois enfouie dans un `calc()`, `alpha()` le détour par `rgb(from … r g b / 0.3)`.
Et une animation liée au défilement n'a plus besoin du moindre écouteur `scroll` :
voir [scroll-driven animations](/css/senior/scroll-animations).

### Dans les trois moteurs, mais pas classé Baseline

- **`text-box`** : livré dans Chrome 133, Safari 18.2 et Firefox 154 (août 2026).
  web.dev l'a annoncé Baseline, mais `web-features` ne le classe pas ainsi : des
  valeurs de `text-box-edge` y restent marquées incomplètes côté Firefox. Teste les
  tiennes — voir [text-box-trim](/css/medior/text-box-trim).
- **Arithmétique typée** : diviser deux longueurs donne un nombre sans unité
  (`calc(100vw / 1px)`). Chrome 140, Safari 26, Firefox 158 (octobre 2026) ;
  `web-features` n'a pas encore d'entrée pour elle.
- **`random()`** : Safari 26.2, Chrome 156, puis Firefox 161 le 24 novembre 2026.
  Deux mots-clés de cache manquent encore dans Safari stable.

:::callout{type="tip"}
« Newly available » n'est pas « Widely available » : ce second palier arrive
**30 mois** plus tard. Si ton parc inclut des navigateurs d'avant mi-2026, garde un
repli. Browserslist comprend ces paliers (`baseline widely available`) : ta cible de
build peut suivre Baseline au lieu d'une liste de versions tenue à la main.
:::

## `if()`, `@function`, `attr()` typé, `corner-shape` : la sortie de Chromium

Une fonctionnalité livrée par un seul moteur reste un pari. Le signal qui compte,
c'est la **deuxième implémentation indépendante**. Elle arrive : les notes de
**Safari 27.3 bêta** (16 novembre 2026) annoncent `if()`, `@function`, `attr()` typé
et `corner-shape`, plus `random-item()` et `text-decoration-inset`.

| Fonctionnalité | Chrome / Edge | Safari | Firefox |
| --- | --- | --- | --- |
| `if()` | 137 | 27.3 bêta | non |
| `@function` | 139 | 27.3 bêta | non |
| `attr()` typé | 133 | 27.3 bêta | 155 |
| `corner-shape` | 139 | 27.3 bêta | Nightly seulement |

:::callout{type="warn"}
**Novembre 2026 : Safari 27.3 est une bêta**, sans date de sortie annoncée, et une
bêta peut encore retirer une fonctionnalité. Firefox ne livre ni `if()` ni
`@function`. Présente-les comme « à venir », pas comme acquises : toujours un repli.
:::

Leur syntaxe et le repli le plus simple (une valeur statique déclarée juste avant)
sont dans [fonctions CSS et mixins](/css/senior/functions-mixins) ; les formes de
coin dans [corner-shape](/css/senior/corner-shape). Le plus avancé est `attr()` typé,
qui lit un attribut HTML **comme un nombre, une longueur ou une couleur** — et plus
seulement comme une chaîne réservée à `content` :

```css
/* HTML : <li class="barre" data-valeur="72">…</li> */
@supports (x: attr(x type(*))) {            /* détection documentée par MDN */
  .barre {
    /* l'attribut devient un nombre utilisable dans calc() ; 0 s'il est absent */
    inline-size: calc(attr(data-valeur type(<number>), 0) * 1%);
  }
}
```

## Décembre 2026 : Firefox 162 active les view transitions cross-document

Les view transitions dans une même page sont Baseline depuis octobre 2025. Il
manquait un moteur pour la version **cross-document** : animer le passage d'une page
à l'autre d'un site multipage, sans JavaScript. Chrome et Edge 126 et Safari 18.2
les gèrent ; Firefox 162 les active par défaut.

```css
@view-transition { navigation: auto; }               /* opt-in, sur les deux pages */
/* Même nom des deux côtés : l'image se déplace au lieu de fondre */
.couverture { view-transition-name: couverture; }
```

:::callout{type="warn"}
**Novembre 2026 : Firefox 162 est en bêta**, sortie prévue le 8 décembre 2026. Dans
Firefox 161 (stable), la navigation se fait sans animation : un dégradé acceptable.
Tu peux donc poser l'opt-in dès maintenant.
:::

La même version apporte `background-clip: border-area` (déjà dans Chrome 150 et
Safari 18.2) : un dégradé peint dans la bordure, sans `border-image`. Pour le reste
de l'API, voir [View Transitions](/web/medior/view-transitions).

## Grid Lanes, select personnalisable, anchor positioning : où en est chaque moteur

Trois gros chantiers, trois stades différents. Le premier a carrément changé de
syntaxe : la maçonnerie native (colonnes à hauteurs décalées, façon Pinterest) ne
s'écrit plus comme on l'annonçait mi-2026.

:::compare
::bad
```css
/* Syntaxe abandonnée : aucun navigateur stable ne l'a jamais livrée */
.galerie {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
  grid-template-rows: masonry;
}
```
::
::good
```css
.galerie {            /* repli : une grille classique, aux rangées alignées */
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
  gap: 1rem;
}
@supports (display: grid-lanes) {   /* chaque élément remonte dans sa colonne */
  .galerie { display: grid-lanes; }
}
```
::
:::

**Pourquoi.** La spécification (CSS Grid Level 3) a retenu une valeur de `display`
dédiée, **Grid Lanes**, plutôt qu'un mot-clé glissé dans Grid. Tu gardes le
vocabulaire des pistes (`grid-template-columns`, `gap`, `minmax()`), mais c'est un
mode de mise en page à part, sans rangées. Le `@supports` isole le mot-clé.

| Chantier | Chrome / Edge | Safari | Firefox | Baseline |
| --- | --- | --- | --- | --- |
| Grid Lanes (`display: grid-lanes`) | pas en stable | 26.4 | Nightly seulement | non |
| `<select>` personnalisable (`appearance: base-select`) | 135 | 27 | derrière une préférence (depuis la 149) | non |
| Anchor positioning | 125 | 26 | 147 | non |

:::callout{type="warn"}
**Novembre 2026 : Grid Lanes n'existe en stable que dans Safari**, et ses réglages
bougent encore — Safari 27.2 a renommé `flow-tolerance` en `fit-tolerance`. Garde ta
bibliothèque de maçonnerie JavaScript pour les autres moteurs.
:::

Le `<select>` personnalisable tient sur deux moteurs depuis Safari 27 (septembre
2026) : voir [styliser les formulaires](/css/medior/modern-form-styling). L'anchor
positioning est livré partout, mais sa spécification a encore bougé en 2026, d'où
l'absence de classement : [anchor positioning](/css/senior/anchor-positioning)
liste ces ajustements.

## Chromium en éclaireur

Chrome continue de livrer en premier. Ces quatre nouveautés n'existent, en novembre
2026, **que dans Chromium** :

```css
.grille {
  display: grid;
  gap: 2rem;
  column-rule: 1px solid var(--bordure);   /* gap decorations (Chrome 149) : */
  row-rule: 1px solid var(--bordure);      /* des filets dans les gouttières */
}
/* text-fit (Chrome 150) : le titre grossit jusqu'à remplir sa ligne */
.titre-affiche { text-fit: grow; }
/* flex-wrap: balance (Chrome 150) : des lignes de longueur voisine */
.etiquettes { display: flex; flex-wrap: balance; }
/* scroll-triggered animations (Chrome 146) : l'animation démarre à un seuil */
.encart {
  timeline-trigger: --apparition view() contain / cover;
  animation: fondu 0.4s both;
  animation-trigger: --apparition play-forwards play-backwards;
}
```

Ne confonds pas les deux familles. *Scroll-driven* : la **progression** de
l'animation suit le défilement. *Scroll-triggered* : le défilement ne fait que
**déclencher** une animation qui se joue ensuite à sa durée normale — le travail que
tu confiais à un `IntersectionObserver`.

:::callout{type="warn"}
**Novembre 2026 : un seul moteur, statut expérimental.** Ni Safari ni Firefox ne les
livrent. Réserve-les à l'amélioration progressive : un filet absent ne casse rien,
une mise en page qui en dépend, si.
:::

## Encore au stade proposition

Trois sujets reviennent dans les annonces, sans rien de livrable :

- **`@mixin` / `@apply`** (réutiliser un bloc de déclarations) : derrière un flag
  dans Chrome depuis la 141, rien dans Safari ni Firefox.
- **`appearance: base` pour les autres contrôles** : le brouillon CSS Forms étend à
  tous les champs ce que `base-select` fait pour `<select>`.
- **CSS spatial** : le brouillon *CSS Spatial Layout Module Level 1* (25 novembre
  2026) étend le positionnement à l'axe z, pour les interfaces en trois dimensions.

:::callout{type="warn"}
**Novembre 2026 : des brouillons d'éditeurs.** Leur syntaxe peut encore changer du
tout au tout — l'épisode `masonry` vient de le rappeler. Aucun code de production.
:::

## À retenir

D'ici mi-2027, ton travail tient en deux gestes : retirer les contournements devenus
inutiles (index posés à la main, écouteurs `scroll`), et ranger chaque nouveauté
derrière le bon niveau de prudence — rien, un repli, ou « pas encore ».
